# 商务楼快递柜满仓转移与超时退回系统

云岸商务楼（A/B 两座）智能快递柜演示系统：包裹扫描入柜、最小格口匹配、满仓转移（人工货架 / 邻楼柜机）、
取件核验、超时队列、退回交接、异常封存与强制开柜审批。**纯 Python 标准库 + 原生前端，零第三方依赖。**

所有姓名、手机号、运单号、取件码均为虚构数据；门锁与短信均为本地模拟适配器。

## 一条命令启动

```bash
./run.sh            # 重置演示数据并在 http://localhost:8000 启动
PORT=9000 ./run.sh  # 指定端口
./run.sh keep       # 保留现有数据启动
./run.sh test       # 运行全部 15 个测试
./run.sh tick       # 对运行中的系统手动触发一次超时/重试扫描
```

需要 Python 3.8+（开发环境 3.11）。数据存于 `data/parcel.db`（SQLite），异常凭证存于 `evidence/`。

## 七个界面

1. **总览**：各柜机满仓率、超时/退回/封存/待审批/待发短信 KPI。
2. **柜机格口图 · 入柜**：格口**严格按大(2×2)/中(2×1)/小(1×1)比例**排布；满仓率徽标在柜机标题旁；
   右侧为**四步连续路径**工作流（扫描 → 匹配/分流 → 关门回执 → 通知），无多层弹窗。
3. **人工货架**：按**架号 → 层号 → 位号**高密度定位；Q 架为异常封存区。
4. **取件核验**：本人核手机尾号；前台代取必须核 4 位授权码 + 被授权人姓名。
5. **超时队列**：超存放时限的包裹；可办理收件人延期（每单限 1 次）。
6. **退回交接**：超时满宽限期自动入队；快递公司签收或**拒收 → 封存 Q 架 + 凭证**。
7. **强开审批**：快递员申请、物业批准/驳回、批准后才能执行。

## 核心业务规则

- **最小可用格口**：按 小→中→大 匹配能容纳包裹的最小格口；柜门**打开未关闭 / 故障时不可分配**。
- **关门回执才算入柜**：开门只抢占格口（`allocating`），`关门回执成功`后包裹才 `stored`，
  随后生成 6 位取件码并下发短信。
- **并发抢锁**：两名快递员争同一格口时，原子 `UPDATE ... WHERE status='free'` 保证只有一人成功，
  另一人收到 409 竞争失败。
- **每次转移作废旧取件码并生成新通知**：码链（active / void / used）与转移链在包裹详情中完整可溯。
- **异常分流**：尺寸不符（开门后改配更大格口）、错投（跨楼拦截 + 凭证 + 转投）、柜门故障（封存 + 强开审批）、
  重复扫码（409 返回当前位置）、收件人延期（限次）、超时无人取（自动退回）、退回拒收（封存 + 凭证）。
- **公司隔离**：普通快递员对他司包裹的详情、扫码、操作、退回签收一律 403；列表只返回本公司。
- **强开审批**：未审批执行返回 403；快递员审批返回 403；物业批准后执行，原取件码作废。
- **进程内调度器**：每 10 秒扫描超时（→ 逾期通知）、逾期满 24h（→ 退回队列）、短信失败重试（最多 5 次）。

## 代码结构

```
app/db.py         SQLite 表结构与连接
app/adapters.py   模拟门锁（开关回执/故障）与短信网关（失败注入/重试回执）
app/services.py   核心业务服务（入柜/转移/取件/超时/退回/强开/隔离）
app/scheduler.py  进程内定时任务（超时、退回入队、通知重试）
app/seed.py       演示种子数据（满仓/故障/超时/拒收/转移链）
app/server.py     HTTP API + 静态资源（标准库 http.server）
app/tests.py      15 个测试：竞争、码失效、转移链、强开审批、公司隔离等
web/              index.html / styles.css / app.js（原生 JS）
evidence/        异常凭证（故障/错投/拒收）本地文件
```
