# 商务楼快递柜满仓转移与超时退回系统

零第三方依赖（Python 3.11 标准库 + SQLite + 原生前端）的端到端演示系统。
姓名、手机号、运单号均为虚构数据。

## 一条命令启动

```bash
./run.sh            # 等价 python3 app.py，默认 http://127.0.0.1:8080
PORT=8099 ./run.sh  # 换端口
```

启动即自动：建库 → 写入满仓 / 故障 / 超时 / 拒收 / 封存演示数据 →
启动 Web 服务与进程内后台任务（超时扫描、短信重试，每 5 秒一轮）。
加 `--keep-data` 可保留上次数据。

- SQLite：`data/locker.db`（包裹、事件、转移、交接、审批、通知）
- 异常凭证目录：`data/evidence/`（退回拒收、异常封存的本地文本凭证）

## 业务规则落点

- **最小可用格口**：按尺寸档位（小<中<大）+ 物理长宽高匹配；门 `open`/`fault`、
  已占用、已锁定的格口均不参与分配。
- **关门回执才算入柜**：争锁 → 门锁开门 → 放件 → 关门成功回执才置 `stored`
  并发码通知；关门瞬间故障则格口报修、包裹退回改投。
- **格口竞争**：`cell_locks` + `BEGIN IMMEDIATE`，两人同抢仅一人成功。
- **满仓转移连续路径**：本楼柜机 → 同楼货架 → 邻楼柜机；每跳作废旧码、
  `code_seq+1`、换新码并短信通知，转移全程记录在 `transfers` 与事件流水。
- **人工货架**：架号 / 层号 / 位号高密度定位，前台凭证取件。
- **取件核验**：本人取件；前台代取必须授权码 + 代取人姓名/手机号双匹配，
  授权一次性；旧码、超时码一律拒绝。
- **延期 / 超时**：收件人可延期；后台任务对到期件置 `ready_return` 并催件。
- **退回交接 / 拒收**：签收完结；拒收留存本地凭证并再次通知收件人。
- **强开**：快递员申请 → 物业审批 → 凭审批号强开取出；故障门强开后保持
  故障态，维修结案前不再分配。
- **公司隔离**：普通快递员对他司包裹的查询、扫码、延期、强开均被拒绝。

## 界面

商务白底 + 深海军蓝侧栏 + 快递橙主操作；柜机格口严格按物理 mm 宽高比排布
（大/中/小分带），满仓率显示在柜机标题旁；入柜与转移是一条连续步骤路径，
不使用多层弹窗。

## 测试

```bash
python3 -m unittest tests.test_system -v   # 17 项服务层测试
# 先 ./run.sh，再：
python3 tests/http_smoke.py                # 8 组 HTTP 端到端场景
```

覆盖：格口竞争、开门未关不可分配、关门回执、尺寸不符与最小匹配、
码失效与转移链、强开审批全链、公司隔离、重复扫码、超时退回、拒收凭证、
前台代取授权、延期、通知重试。
